# معماری Runtime سامانه IranOS

## هدف

این سند معماری Runtime سامانه IranOS را تعریف می‌کند.

Runtime Architecture مشخص می‌کند که سامانه چگونه به‌صورت واقعی اجرا می‌شود، چگونه boot می‌شود، چگونه قراردادها و عامل‌ها فعال می‌شوند، چگونه داده وارد سامانه می‌شود و چگونه عملیات در سطح اجرایی و زنده مدیریت می‌شوند.

این لایه مرز میان سپیدنامه مفهومی و سامانه عملیاتی واقعی است.

---

# تعریف Runtime

Runtime یعنی وضعیت زنده و فعال سامانه.

Runtime شامل:

- هسته فعال
- قراردادهای deploy شده
- عامل‌های فعال
- اوراکل‌های متصل
- دفترکل در حال ثبت
- عملیات در حال اجرا
- وضعیت امنیتی جاری

است.

---

# اصول Runtime

## ۱. Runtime باید قابل توقف باشد

هیچ بخش سامانه نباید غیرقابل مهار باشد.

---

## ۲. Runtime باید قابل حسابرسی باشد

تمام عملیات Runtime باید ثبت شوند.

---

## ۳. Runtime باید منشور را enforce کند

هیچ عملیات زنده‌ای نباید خارج از محدودیت‌های منشور اجرا شود.

---

## ۴. Runtime باید ماژولار باشد

تمام اجزا باید جداشدنی، قابل تعلیق و قابل جایگزینی باشند.

---

## ۵. Runtime باید مقاوم باشد

سامانه باید در برابر:

- نفوذ
- فساد
- رفتار غیرعادی
- خرابی اوراکل
- خطای عامل‌ها
- حملات مالی

مقاومت داشته باشد.

---

# اجزای Runtime

## ۱. Kernel Runtime

هسته زنده سامانه.

وظایف:

- مدیریت نقش‌ها
- مدیریت مجوزها
- مدیریت وضعیت اضطراری
- کنترل قراردادها
- کنترل عامل‌ها
- کنترل دسترسی Runtime
- هماهنگی اجزای سامانه

Kernel مرکز هماهنگی Runtime است.

---

## ۲. Contract Runtime

قراردادهای deploy شده و فعال.

شامل:

- قراردادهای پولی
- قراردادهای حکمرانی
- قراردادهای درآمد ملی
- قراردادهای قضایی
- قراردادهای اضطراری
- قراردادهای هویتی

هر قرارداد دارای:

- وضعیت فعال
- سطح حساسیت
- سطح دسترسی
- وضعیت امنیتی
- مسیر حسابرسی

است.

---

## ۳. Agent Runtime

عامل‌های هوشمند فعال.

شامل:

- عامل مالی
- عامل هویتی
- عامل امنیتی
- عامل حسابرسی
- عامل اقتصادی
- عامل تحلیل ریسک

وظایف عامل‌ها:

- تحلیل داده
- تولید پیشنهاد
- تشخیص ناهنجاری
- تحلیل وضعیت
- هشدار امنیتی

عامل‌ها نباید کنترل کامل Runtime را داشته باشند.

---

## ۴. Oracle Runtime

اوراکل‌های متصل به Runtime.

وظایف:

- ورود داده واقعی
- همگام‌سازی وضعیت
- ثبت داده خارجی
- ثبت داده اقتصادی
- ثبت داده امنیتی
- ثبت داده هویتی

اوراکل‌ها فقط feed provider هستند.

---

## ۵. Ledger Runtime

دفترکل زنده سامانه.

وظایف:

- ثبت رخدادها
- ثبت عملیات
- ثبت حسابرسی
- ثبت وضعیت Runtime
- ذخیره مسیر بازسازی
- ذخیره هشدارهای امنیتی

Ledger حافظه زنده کشور است.

---

## ۶. Security Runtime

لایه امنیت Runtime.

وظایف:

- تشخیص نفوذ
- تشخیص رفتار غیرعادی
- تشخیص دسترسی غیرمجاز
- تشخیص حمله مالی
- تشخیص دستکاری داده
- فعال‌سازی قفل اضطراری

---

# Runtime Permission Model

هیچ Runtime Object نباید:

- خارج از سطح دسترسی خود عمل کند
- منشور را override کند
- دفترکل را دور بزند
- رخدادها را حذف کند
- عملیات اضطراری را غیرفعال کند

---

# Runtime Security Rules

تمام Runtime Components باید:

- قابل توقف باشند
- قابل حسابرسی باشند
- محدودیت دسترسی داشته باشند
- مسیر بازسازی داشته باشند
- رخداد ثبت کنند

---

# Runtime Emergency Model

در صورت وضعیت خطرناک:

- Runtime مالی محدود می‌شود
- Runtime قراردادها قفل می‌شود
- Runtime عامل‌ها تعلیق می‌شود
- Runtime امنیتی فعال می‌شود
- دفترکل وارد وضعیت ثبت اضطراری می‌شود

---

# Runtime Isolation

هیچ عامل یا قرارداد نباید بتواند:

- کنترل کامل Runtime را بگیرد
- دسترسی سایر بخش‌ها را حذف کند
- منشور را دور بزند
- وضعیت اضطراری را غیرفعال کند

---

# Runtime Audit

تمام عملیات Runtime باید شامل:

- زمان اجرا
- منبع عملیات
- شناسه عامل
- وضعیت امنیتی
- نتیجه عملیات
- وضعیت منشور

باشند.

Runtime سامانه IranOS در مرحله تعریف معماری اجرایی قرار دارد.
