# VS-01 — یادداشت تصمیم‌های باز حاکمیت گواهی‌دهی (Attestation Governance)

**نوع سند:** یادداشت تصمیم باز (open-decision note) — مستندات‌محور  
**workstream:** VS-01 (پیوند VotingSystem ↔ CitizenCard)  
**وضعیت:** باز؛ نیازمند تصمیم انسانی/حاکمیتی  
**تاریخ:** ۱۴۰۵/۰۳/۲۴ (۲۰۲۶-۰۶-۱۴)

> این سند صرفاً تصمیم‌های باز را **ثبت** می‌کند. هیچ تصمیمی نمی‌گیرد، هیچ نهاد یا اختیاری ایجاد نمی‌کند، و VS-01 را نمی‌بندد.

-----

## ۱. وضعیت

- VS-01 همچنان **OPEN / Defer** است (مطابق تعیین تکلیف گام ۱۳).
- این سند VS-01 را **نمی‌بندد**.
- این سند هیچ **اختیار، نقش، نصاب، یا نهاد** جدیدی ایجاد نمی‌کند.
- طراحی معماری VS-01 تا حل «حاکمیت گواهی‌دهی» از راه تصمیم انسانی/حاکمیتی **مسدود** است.

-----

## ۲. پرسش دقیق تصمیم

> چه کسی گواهی واجد شرایط بودن (eligibility attestation) را تولید می‌کند، تحت چه سازوکار چندمنبعی و پاسخگویی‌ای، تا `VotingSystem` بتواند **حکمِ واجد شرایط بودن** را مصرف کند بدون آنکه به یک مرجع پنهانِ یگانه اعتماد کند؟

-----

## ۳. چهار زیرپرسش باز

1. **هویت گواهی‌دهنده (Attestor identity):** کدام نهاد(ها) یا نقش(ها) گواهی واجد شرایط بودن را صادر می‌کنند و تضمین استقلال آن‌ها چیست؟
2. **قاعده چندمنبعی (Multi-source rule):** حداقل تعداد منابع مستقل چقدر است و در صورت اختلاف، حل‌وفصل چگونه انجام می‌شود؟
3. **پاسخگویی / حسابرسی / ضمانت اجرا (Accountability / audit / sanction):** گواهی‌دهندگان چگونه حسابرسی می‌شوند و پیامد یک گواهی نادرست چیست؟
4. **اختیار ابطال / اصلاح (Revocation / correction authority):** چه کسی می‌تواند یک واقعیتِ واجد شرایط بودن را پس بگیرد یا اصلاح کند و بر چه مبنایی؟

-----

## ۴. محدودیت‌های موجود (constraints)

- **بدون شورای نگهبان / بدون رد صلاحیت سلیقه‌ای** — گواهی‌دهی، اثباتِ واقعیت است نه تأیید اختیاری؛ هیچ مرجعی حق رد نامزدِ واجد شرایط را ندارد (ارجاع: [پروتکل حاکمیت](../../protocols/governance-protocol-fa.md) §۳.۲).
- **اوراکل سیگنال است نه حاکمیت** — ورودی‌ها باید قابل حسابرسی و چندمنبعی باشند (ارجاع: `docs/Doctrine/INTERPRETATION_BOUNDARIES_FA.md` §۵).
- **شفافیت شیشه‌ای / حریم خصوصی شهروند** — گواهی باید **واقعیت** را آشکار کند، نه داده‌های شخصی شهروند (ارجاع: `docs/Doctrine/GLASS_TRANSPARENCY_FA.md`).
- **شهروند ≠ رأی‌دهنده** — صدور هویت، رأی‌دهنده نمی‌سازد (ارجاع: [پروتکل انتخابات](../../protocols/election-protocol-fa.md) §۸).
- **حکمِ واجد شرایط بودن ≠ منطق واجد شرایط بودن** — `VotingSystem` تنها حکم را می‌گیرد، نه دلیل یا داده منبع را.

-----

## ۵. مالکیت (ownership)

- **مالک اصلی:** پروتکل حاکمیت / **تصمیم حاکمیتی انسانی**.
- **نه** ElectionProtocol (تنها ارجاع می‌دهد، مطابق قاعده نگارش §۱.۴ آن).
- **نه** کد.
- **نه** بازنویسی منشور (معیارهای واجد شرایط بودن از پیش در منشور و پروتکل حاکمیت‌اند).

-----

## ۶. خطوط نگه‌دارنده (guardrails)

هر کس این موضوع را حل می‌کند، نباید:

- نهادِ ردکننده نامزد ایجاد کند (مغایر §۳.۲ پروتکل حاکمیت).
- یک گواهی‌دهندهٔ سلطانِ یگانه تعریف کند (مغایر دکترین اوراکل).
- معیارهای واجد شرایط بودن را تعریف کند (متعلق به منشور).
- طراحی ذخیره‌سازی، رابط، یا قرارداد انجام دهد (معماریِ پس از این پیش‌نیاز).
- VS-01 را ببندد.

-----

## ۷. اقدام بعدی لازم

ثبت یک **تصمیم انسانی/حاکمیتی** درباره چهار زیرپرسش §۳ — با مالکیت پروتکل حاکمیت و اِسناد قابل ردیابی (هم‌سو با انضباط شواهد گام ۱۲/۱۳، بدون اختراع امضاکننده) — **پیش از** آغاز طراحی معماری VS-01.

-----

> این یادداشت بخشی از مجموعه مستندات گام ۱۳ ایران‌اواس است و صرفاً مستندات‌محور است؛ نیازمند بازبینی انسانی/حاکمیتی است.
