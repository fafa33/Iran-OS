## چرا مشارکت؟

ایران‌اواس یک پروژه متن‌باز (Open Source) است. کدهایی که اینجا نوشته می‌شوند، روزی سیستم‌عامل یک کشور ۸۵ میلیون نفری را اجرا خواهند کرد. هیچ پروژه‌ای در تاریخ برنامه‌نویسی ایرانی این مقیاس و این اهمیت را نداشته است.

مشارکت شما سه اثر مستقیم دارد:

۱. **اثر فنی:** کدی که می‌نویسید مستقیماً در لایه‌های حاکمیتی ایران اجرا می‌شود
۲. **اثر تاریخی:** نام شما به عنوان «بنیان‌گذار فنی» در بلاک‌چین ثبت دائمی می‌شود
۳. **اثر مالی:** مشارکت‌کنندگان فاز صفر با اولویت مطلق از محل اولین بازیابی‌های صندوق ثروت ملی دستمزد دریافت می‌کنند

## فرایند مشارکت فنی

### گام ۱: آشنایی با پروژه

پیش از هر اقدامی این مستندات را مطالعه کنید:

```
۱. منشور رفاه و عدالت          → /constitution/
۲. سپیدنامه فنی ایران‌اواس     → /whitepaper/whitepaper-fa.md
۳. پروتکل مرتبط با حوزه کارتان → /protocols/
۴. واژه‌نامه فنی                → /docs/glossary-fa.md
```

### گام ۲: انتخاب یک Issue

- Issues با برچسب `good-first-issue` برای تازه‌واردان مناسب است
- Issues با برچسب `core` نیازمند تجربه بیشتر است
- Issues با برچسب `urgent` اولویت فوری دارند

### گام ۳: Fork و Clone

```bash
# Fork کردن ریپو از گیت‌هاب
# سپس Clone کردن Fork خودتان
git clone https://github.com/[username]/Iran-OS.git
cd Iran-OS

# ساخت Branch جدید
git checkout -b feature/[نام-ویژگی]
# یا
git checkout -b fix/[نام-باگ]
```

### گام ۴: توسعه و تست

```bash
# نصب وابستگی‌ها
npm install
# یا
pip install -r requirements.txt

# اجرای تست‌ها
npm test
# یا
pytest

# اطمینان از اجرای موفق تمام تست‌ها قبل از Commit
```

### گام ۵: Commit و Push

```bash
# استاندارد پیام Commit (فارسی یا انگلیسی)
git commit -m "feat(trigger): اضافه کردن لایه تشخیص تخلف TR-02"
git commit -m "fix(monetary): رفع باگ در محاسبه نسبت پشتوانه"
git commit -m "docs(glossary): اضافه کردن تعریف ZK-Rollups"

git push origin feature/[نام-ویژگی]
```

### گام ۶: Pull Request

در Pull Request خود حتماً ذکر کنید:

- **مشکل حل شده:** کدام Issue یا نیاز
- **راه‌حل:** توضیح مختصر رویکرد فنی
- **تست‌ها:** نتایج تست‌ها
- **ارتباط با منشور:** کدام بخش منشور یا سپیدنامه پوشش داده شده
- **ملاحظات امنیتی:** اگر تغییر روی امنیت تأثیر دارد

## فرایند مشارکت مستنداتی

### ویرایش مستندات موجود

۱. فایل مورد نظر را در گیت‌هاب باز کنید
۲. روی آیکون ✏️ (Edit) کلیک کنید
۳. تغییرات را اعمال کنید
۴. توضیح تغییر را در بخش Commit بنویسید
۵. Pull Request بزنید

### افزودن مستندات جدید

- فایل‌های فارسی با پسوند `-fa.md` نام‌گذاری شوند
- فایل‌های انگلیسی با پسوند `-en.md`
- ساختار `<div dir="rtl">` برای فارسی الزامی است
- فهرست لینک‌دار در ابتدای هر فایل اضافه شود

## استانداردهای کد و مستندات

### استانداردهای کد

```
✅ کدهای هوشمند باید Audit شده و تست‌های جامع داشته باشند
✅ هر تابع باید مستند (NatSpec برای Solidity) باشد
✅ پوشش تست (Test Coverage) حداقل ۹۵٪
✅ هیچ Secret یا کلید خصوصی در کد نباشد
✅ کدها باید با اصول منشور انطباق داشته باشند
❌ هیچ Backdoor یا دسترسی Admin مخفی مجاز نیست
❌ کدی که امکان دور زدن پروتکل ماشه را فراهم کند مردود است
```

### استانداردهای مستندات

```
✅ راست‌چین (<div dir="rtl">) برای فارسی
✅ فهرست لینک‌دار در ابتدای فایل
✅ استفاده از اصطلاحات واژه‌نامه (glossary-fa.md)
✅ لینک به بخش‌های مرتبط منشور و سپیدنامه
✅ نسخه و تاریخ در هدر فایل
❌ محتوای ایدئولوژیک، مذهبی یا حزبی مجاز نیست
❌ ادعاهای بدون مستند و منبع مجاز نیست
```

## پروتکل پاداش و ثبت مشارکت

### ثبت دائمی در بلاک‌چین (Proof of Contribution)

نام و میزان مشارکت هر متخصص بر بستر بلاک‌چین پروژه ثبت شده و **غیرقابل حذف** است. این ثبت شامل:

- شناسه دیجیتال مشارکت‌کننده
- حوزه و میزان مشارکت (خطوط کد، مستندات، Audit)
- تاریخ و نسخه مشارکت
- امتیاز کیفی بر اساس بازبینی همتایان (Peer Review)

### سطوح مشارکت و عناوین

|سطح|معیار                        |عنوان                                |
|---|-----------------------------|-------------------------------------|
|۱  |اولین Pull Request پذیرفته‌شده|مشارکت‌کننده (Contributor)            |
|۲  |۱۰ مشارکت پذیرفته‌شده         |مشارکت‌کننده فعال (Active Contributor)|
|۳  |مشارکت در یک پروتکل اصلی     |معمار پروتکل (Protocol Architect)    |
|۴  |مشارکت در لایه صفر           |معمار هسته (Core Architect)          |
|۵  |رهبری یک حوزه اصلی           |بنیان‌گذار فنی (Technical Founder)    |

### پاداش مالی (Retroactive Funding)

پس از استقرار دولت موقت:

- **بنیان‌گذاران فنی (سطح ۵):** دستمزد تخصصی با اولویت مطلق از محل اولین بازیابی‌های صندوق
- **معماران هسته (سطح ۴):** دستمزد بر اساس ارزش‌گذاری مشارکت در بلاک‌چین
- **معماران پروتکل (سطح ۳):** دستمزد از محل صندوق Bounty Program
- **مشارکت‌کنندگان فعال (سطح ۲):** پاداش از محل صندوق Bounty Program
- **مشارکت‌کنندگان (سطح ۱):** توکن تقدیر (Recognition Token) در بلاک‌چین

### صندوق Bounty Program

یک صندوق ارز دیجیتال تحت نظارت هیئت امنای فنی برای پاداش فوری به:

- کشف باگ‌های امنیتی حیاتی
- بهبودهای فنی کلان
- تولید مستندات با کیفیت بالا
- ترجمه به زبان‌های اقلیت‌های ایرانی

## آیین‌نامه رفتاری

### اصول پایه

**احترام به تنوع:** جامعه ایران‌اواس شامل ایرانیان از همه اقوام، مذاهب، جنسیت‌ها و دیدگاه‌های سیاسی است. احترام متقابل پایه همکاری است.

**بی‌طرفی سیاسی در کد:** کدها و مستندات باید خنثی، فنی و مبتنی بر منشور باشند. تریبون پروژه برای تبلیغ احزاب یا جریانات سیاسی نیست.

**شفافیت کامل:** هر تصمیم فنی کلان باید در فضای عمومی بحث و مستند شود. تصمیم‌گیری در اتاق‌های بسته با روح پروژه در تضاد است.

**علم‌محوری:** اختلاف‌نظرها باید با داده، آزمایش و استدلال فنی حل شوند، نه با حمله شخصی یا اقتدار.

### رفتارهای ممنوع

```
❌ آزار، تهدید یا تحقیر سایر مشارکت‌کنندگان
❌ انتشار اطلاعات شخصی دیگران بدون رضایت
❌ تلاش برای معرفی Backdoor یا کد مخرب
❌ ادعای مشارکت بدون انجام کار واقعی
❌ استفاده از تریبون پروژه برای اهداف سیاسی حزبی
```

### گزارش تخلف

در صورت مشاهده رفتار نامناسب، از طریق Issue خصوصی یا ایمیل تیم امنیت گزارش دهید. تمام گزارش‌ها محرمانه بررسی می‌شوند.
